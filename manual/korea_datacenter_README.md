# 국내 데이터센터

`지엔씨_수전용량.xlsx`의 `데이터센터(정리)` 97개 행을 기준으로 가져왔다. 드라이브 원본은 변경하지 않는다. 수주·금액·사업자번호 및 원본 엑셀 파일은 배포 데이터에 포함하지 않는다. 선택된 센터 현황·용량·메모·참고 URL은 대시보드 데이터에 저장한다.

## 기준자료 재수입

구글 드라이브에서 최신 원본을 읽어 로컬에 내려받은 뒤 다음 명령을 사용한다. 대시보드의 일간 수집에는 드라이브 인증이 없으므로 기준 엑셀을 다시 읽지 않는다.

```sh
python scripts/korea_datacenter.py --import-xlsx /path/to/source.xlsx --snapshot-date YYYY-MM-DD
python scripts/fetch_korea_datacenter.py --offline
```

기준 시점에는 원본의 실제 수정일을 사용한다. `manual/korea_datacenter_baseline.json`은 선택 항목과 Raw의 연결 자료만 저장하며 원본 파일 전체를 복제하지 않는다. 수전용량·IT Load·소유자·시공사·URL·셀 메모는 기준 값이 우선이다. 기준자료의 빈 건축구분은 임의로 신축으로 바꾸지 않는다. 날짜 표기의 원문을 보존하며 잘못된 달력 날짜, 연도·분기만 있는 값, 목표·예정 날짜는 확정 집계에서 제외한다.

## 자동 수집

`python scripts/fetch_korea_datacenter.py`는 BLCM 맞춤형 공개 자료 목록을 확인하고 최신 전국 건축허가 2개 기간과 착공 자료 1개를 수집한다. 최초에는 겹치는 허가 기간을 가져와 기준 Raw 이후의 2026년 5~8월을 보완한다. 이후 신규 게시물만 읽고 기존 관측 이력을 유지한다. 원본 XLSX 캐시는 `.cache/korea_datacenter/`에만 저장하며 Git에서 제외한다.

`update-data.yml`의 매일 KST 07:30 실행에 포함된다. 수동으로 해당 자료만 확인할 때는 `datacenter_only` 입력을 사용한다. API 키는 필요하지 않다. 공개 통계는 요청에 따라 게시되므로 동일 기준의 자료가 매월 제공된다는 보장은 없다. 건축HUB API는 인증키를 사용한 실제 조회 검증 전이므로 이번 자동 수집에 포함하지 않았다.

## 집계와 매칭

- 허가 PK가 같으면 반복 관측을 연결한다. PK가 없거나 과거/건축HUB의 서로 다른 PK 형식일 때는 정규화한 주소·허가일·건축구분을 보조로 사용한다. 같은 PK 형식의 서로 다른 허가는 같은 대지·날짜여도 합치지 않는다.
- 기준 정리 목록과는 주소+허가/변경일을 우선 사용한다. 주소가 불완전한 경우에만 정확한 건물명+날짜를 보조로 사용한다. 복수 기준 행과 일치하면 자동 보완하지 않는다.
- 기타용도에 데이터센터가 명시된 새 공식 허가는 확인 목록에 넣는다. 건물·동 명칭으로만 추출한 자료와 기준 목록에 연결되지 않은 Raw 행은 후보로 분리하고 차트에서 제외한다. 분류를 확정하려면 기준 엑셀 또는 기준 JSON의 해당 행을 검토·수정하고 재생성한다.
- 허가 전체 연면적이 여러 동에 반복되어도 한 번만 사용한다. 같은 관측 안에서 총면적이 서로 다르면 값을 비워두고 면적 후보를 저장한다. 기준 면적과 공식 면적이 다르면 기준 값을 유지하고 검토 내역에 남긴다.
- 빈 날짜·예정 날짜는 확실히 연결된 원자료의 유효한 과거 날짜로 보완한다. 기존 확정 날짜가 다르면 덮어쓰지 않고 검토 내역을 남긴다. 착공처리일/사용승인일 등 행정 기록이 실제 현장 사건일과 일치한다고 단정하지 않는다.
- 같은 센터의 단계별 허가·증축이 포함되므로 표의 행 수는 고유 시설 수가 아니다. 차트는 추적 목록의 확인된 단계별 연도 집계이며 전국 전체 수·면적·수전용량을 추정하지 않는다. 용량 없는 시설을 0MW로 대체하지 않는다.
- 수집 실패 시 마지막 성공 관측과 날짜를 유지하고 오류를 표시한다. 미수집 연도·기간을 0건으로 추가하지 않는다. 당해 연도 값은 현재까지 확인된 자료다.

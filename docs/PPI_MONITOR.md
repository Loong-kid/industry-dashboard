# PPI 모니터 통합

KPI의 `PPI` 탭 (`#/ppi`)은 대표 산업 지도에서 시작한다. 기존 비교·스캐너도 유지한다.

- 대표 산업 지도: 12개 대분류, 기준월 관측값이 있는 공식 산업지수 75개, 최근 12개월 YoY 히트맵, ΔYoY(%p), CSV. 대표 수는 관측 가용성에 따라 달라진다.
- 관심 테마: 반도체·전자부품, ESS·전력설비, 조선·해운, 구리·금속, 건설·데이터센터. 여러 테마에 동시에 속할 수 있다.
- 산업 계층 탐색: 산업 코드 상위·하위 관계를 펼쳐 보고 산업 전체 / 주력제품 / 세부 품목 / 부차적 제품 / 기타 수입을 구분한다.
- Detail: 대분류·섹터·종류·관측 상태 필터 또는 전체 카탈로그 AND 검색, 최대 8개 비교, 요약 및 FRED 원문.
- Table: 최근 6~36개월, 최신값·YoY·MoM, 정렬, 100행 페이지, 전체 결과 CSV. 기본적으로 기준월 관측값이 있는 시리즈만 표시한다.
- 변화 탐지: YoY/MoM 상승률 상위 4~24개 미니 차트. 개별 산업 전체 지수만 사용하고 같은 3자리 산업 계열에서 한 지표씩 표시한다. 광범위한 종합지수는 산업 지도에서 비교한다. 기존 `#/ppi/overview` 주소는 이 화면으로 연결된다.
- 내 관심 목록: 지표의 ☆로 추가·해제. 이 브라우저의 localStorage에만 저장한다.
- 차트: Level / YoY % / MoM % / Indexed (=100), 1Y / 3Y / 5Y / 10Y / 20Y / MAX.

화면은 KPI 테마를 따르며 모바일에서는 보기·필터 설정을 접어두고 데이터부터 보여준다.
Streamlit 서버나 기존 PPI-Monitoring URL을 사용하지 않는다.

## 분류와 대표 선정

`assets/ppi-classification.js`가 코드 반복 구조를 풀어 산업 코드와 제품 접미사를 분리한다.
NAICS 숫자 코드 외에 문자 포함 산업 코드와 특수 종합지수도 처리한다.
기존 산업 메타데이터와 코드 접두사를 조합해 6,135개를 12개 탐색용 대분류에 한 번씩 배정한다.
분류는 가격지수를 새로 합산하는 방식이 아니다. 공식 산업지수를 개별로 보여준다.

대표는 기준월 값이 있는 3자리 산업지수·기존 종합지수를 먼저 선택하고,
반도체·반도체 장비·전지·변압기·스위치기어·조선·철강·구리 가공·냉방 장비를 추가한다.
3자리 지수가 없는 건설·은행·부동산·전문서비스·외래 의료는 이용 가능한 얕은 단계의 산업지수를 선택한다.
FRED 인기도나 세부 품목 개수로 경제적 비중을 추정하지 않는다.

`data/ppi/navigation.json`에는 모든 시리즈의 실제 최종 관측월이 있다.
수집기는 매번 전체 이력에서 이 파일을 함께 갱신하므로 제목의 DISCONTINUED 표기에만 의존하지 않는다.
기준월 관측 / 최근 3개월 관측 / 전체 이력 / 과거·공백 필터를 제공한다.
기준월에서 3개월보다 오래된 관측은 과거·공백으로 표시하며 폐지로 단정하지 않는다.
과거 데이터는 계층 탐색과 비교 화면에서 계속 조회할 수 있다.

## 데이터 및 성능

기존 FRED Industry Based 카탈로그 6,135개를 이관했다. 카탈로그 분류의
기준일(`catalog_built`)과 관측값 수집일(`updated`)은 별도로 보존한다.
FRED 공개 CSV를 CI에서 묶음 수집하므로 추가 API 키가 필요 없다.
기존 Overview/Table의 BLS 벌크 대신 동일 시리즈의 FRED 원값을 사용한다.
Detail의 실시간 API 요청은 마지막 성공 수집 시점의 전체 이력으로 바뀌었다.
실시간 요청이 필요하면 시리즈의 FRED 링크를 이용한다.

PPI 자바스크립트와 카탈로그는 PPI 탭을 열 때만 읽는다. 스캐너는 선택한
섹터의 최근 49개월만 읽고, 차트는 표시할 시리즈의 전체 이력만 읽는다.
YoY/MoM은 행 위치가 아닌 정확한 달을 기준으로 계산하며 빈 관측값은 채우지 않는다.
Indexed 비교는 선택한 시리즈 모두에 유효한 값이 있는 동일 기준월을 100으로 둔다.
공통 기준월이 없는 경우 기간 또는 비교 시리즈를 바꾸도록 안내한다.
스캐너는 100행씩 표시하며 CSV에는 필터·정렬을 반영한 전체 행이 포함된다.
PPI를 떠나거나 표시 옵션을 바꾸면 차트 인스턴스를 정리한다.

## 갱신

`update-ppi.yml`은 매월 10~20일과 매주 월요일 한국 시간 08:00에 수집한다.
KPI의 상단 `PPI 갱신`도 이 워크플로만 실행한다. 기존 갱신 버튼과 동일한
GitHub Actions 권한을 사용한다. 자동 갱신에는 사용자 토큰이 필요 없다.
네트워크/파싱 실패 시 CI가 실패하고 기존 배포 데이터를 보존한다.
성공한 수집 뒤 `publish-data.yml`이 KPI 사이트를 다시 배포한다.

로컬 갱신:

```powershell
python scripts/fetch_ppi.py
python -m unittest discover -s scripts -p test_ppi.py
node scripts/test_ppi.cjs
```

관측 상태 메타데이터만 저장된 이력에서 다시 만들 때는 `python scripts/build_ppi_navigation.py`를 실행한다.

카탈로그를 갱신할 때는 기존 `build_catalog.py`로 생성한 분류를 명시한다:

```powershell
python scripts/fetch_ppi.py --catalog ../ppi-monitor/data/catalog.json
```

## 기존 배포 종료

통합된 KPI 배포에서 세 가지 보기와 자동 수집이 정상 동작하는 것을 확인한 뒤
기존 Streamlit Community Cloud 앱을 종료할 수 있다. PPI-Monitoring GitHub 저장소와
로컬 원본은 이력 보존용으로 남길 수 있으며 통합 사이트는 이에 의존하지 않는다.
PPI-Monitoring은 GitHub Pages 사이트가 아닌 Streamlit 배포이므로 실제 종료는
Streamlit 앱 관리 화면에서 수행한다.

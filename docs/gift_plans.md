# 주식 증여 계획 공시

기관 탭 이름은 `기관`이며, 기존 국내 공시와 미국 운용사·헤지펀드 데이터는 그대로 유지한다.
증여 탭은 `주식 증여 / 수증 계획`과 기존 소유상황 보고 기반 실제 내역을 별도 표로 표시한다.
계획과 실제 수량을 합산하거나 기간 경과만으로 완료를 추정하지 않는다.

## 법적 기준

확인일: 2026-10-05. 투자·법률 판단이 아니라 공시 모니터링용 기준 설명이다.

- 근거: [자본시장법 제173조의3](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1032437031), [시행령 제200조의3](https://law.go.kr/lsLinkCommonInfo.do?lspttninfSeq=189255), [금감원 기업공시 길라잡이](https://dart.fss.or.kr/info/main.do?menu=340).
- 2024-07-24 시행된 상장회사 임원·주요주주의 내부자거래 사전공시 제도다. 주요주주는 의결권 주식 10% 이상 소유 또는 주요 경영사항에 사실상 영향력을 행사하는 경우 등이 해당한다. 단순한 모든 주주나 모든 증여가 대상인 제도는 아니다.
- 거래계획 개시일 기준 과거 6개월 거래와 해당 계획을 합산한 거래수량이 특정증권등 총수량의 1% 미만이고 거래금액도 50억 원 미만이면 규모에 따른 보고의무 면제다. 즉 어느 하나의 기준 이상이면 원칙적으로 보고 대상이다. 주권 외 특정증권등의 수량 환산과 총수량 산정은 단차규정 제9조의5에 따른다.
- 거래 개시일 30일 전까지 보고하며 거래기간은 30일 이내다. 보고자는 거래기간 종료 전 새로운 계획을 보고할 수 없고, 허용된 거래금액 범위 내 실행 또는 정해진 부득이한 사유에 따른 철회가 가능하다.
- 연기금·집합투자기구 등 일부 보고자와 상속·주식배당 등 법정 거래 유형은 제외된다. 일반적인 증여는 시행령의 포괄적인 면제 항목이 아니므로 요건에 따라 보고 대상이 될 수 있다. 수증자 개인의 보고의무는 그 수증자가 임원·주요주주인지 등 별도로 판단해야 한다.
- [금융위원회 시행 안내](https://www.fsc.go.kr/po010101/82635). 2022년 도입 **방안** 자료는 증여 등을 예외로 제시했지만, 실제 2024년 시행 법령과 구분해야 한다.

대시보드는 제출된 보고서에서 증여 계획을 찾아낸다. 시가를 대입해 보고 의무나 위법 여부를 추정하지 않는다. 특히 단가·금액이 `-`이면 0원으로 바꾸거나 가상 거래금액을 만들지 않는다.

## 수집·파싱

- `fetch_gift_plans.py`: [OpenDART `list.json` 공식 개발가이드](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001)의 거래계획 전용 상세유형 `D005`로 특정증권등 거래계획 보고서만 조회한다. 실제 소유상황 보고는 `D002`를 사용한다. 코스피·코스닥 대상이며 기본 확인은 제도 시행일인 2024-07-24부터다. 매일 전체 D005 목록을 재확인해 **이전에 제출된 보고서의 정정·철회 상태 변화**도 갱신한다. 원문은 신규·실패·파서 버전 변경 시에만 다시 조회한다. 증여가 없는 날도 확인일이 진행된다.
- 원문 `document.xml`의 **미래 거래계획 표**(`MDF_STR_DT`/`MDF_END_DT`가 있는 표)에서 `MDF_MT`가 증여/수증이고 `STR_KND`가 주식인 행만 수집한다. 이전 6개월 표의 동일 거래방법·수량 필드, 거래규모 합계, 첨부 계약서는 미래 증여로 분류하지 않는다.
- 동일 보고서에 여러 수증자·거래가 있으면 행을 보존한다. 날짜 rowspan은 그 미래 표 안에서만 상속한다. CB 등 주권 외 증권의 환산 수량을 증여 주식 수로 표시하지 않는다.
- 보고자·회사·수량·방향 부호·날짜·지분율을 검증한다. 수량 누락, 방향 불일치, 미래 표 미식별은 실패로 기록하고 재시도한다. 원문 전체를 공개 저장하지 않으며 연락처·주소·생년월일도 추출하지 않는다.
- OpenDART 목록의 공식 `rm` 표기 `정`(후속 정정신고 있음), `철`(철회됨)을 우선 사용한다. 후속 정정에서 증여가 빠지더라도 이전 원문에는 `정` 표기가 반영되므로 활성 목록에 남기지 않는다. 정정 보고서도 `D005` 조회에 포함하여 그 원문을 파싱한다. 같은 회사·이름이라는 이유로 별도 계획을 합치지 않는다.
- 최초 조사에서 DART 보고서 선택 화면 `select#family`로 확인한 접수번호 연결은 보존하며, 연결된 최신 문서를 확인하지 못한 경우는 `최신 보고서 확인 필요`로 표시한다. HTML 화면이 대량 조회 중 연결을 끊는 문제가 있어 정기 수집은 공식 API만으로 동작한다. 모든 정정 공시를 원본 접수번호와 연결했다고 주장하지 않으며, 별도 최신 링크가 없는 행은 원문 화면의 정정 보고서 선택으로 확인한다.
- `data/_dart/gift_plan_reports.json`에는 거래계획별 성공·실패 상태, 파서 버전, 원문 해시, 최소 목록 정보와 파싱 결과를 보관한다. 증여가 아닌 계획도 확인 결과를 저장해 매번 원문을 반복 조회하지 않는다. 전송 예외에는 키가 포함될 수 있으므로 예외 URL을 로그에 출력하지 않는다.
- 문서 처리 실패는 전체 데이터 삭제를 유발하지 않는다. 기존 성공 결과와 실패 목록을 원자적으로 체크포인트하고, 문서 실패가 있으면 수집 단계는 비정상 종료한다. 기존 workflow의 실패 격리 설정에 따라 다른 지표 갱신은 계속된다.
- `aggregate_gift_plans.py`가 `data/gifts/gift_plans.json`을 만든다. 현재→계획 후 지분율은 **보고서 전체 계획**의 주권 소유비율이며 해당 증여 행만의 변화라고 추정하지 않는다.

## 표시·갱신

- 상태: 계획 공시 / 거래기간 중 / 기간 경과·이행 미확인 / 철회 / 정정 전 / 최신 보고서 확인 필요. 날짜 상태는 브라우저에서도 한국 시간으로 계산한다.
- 정정 전·철회·최신 미확인·소액임원은 기본 숨김이지만 필터를 켜면 확인 가능하다. 원문 및 최신 연결 보고 링크를 제공한다.
- 계획에 공시일·거래 예정기간·예정 수량·현재/계획 후 예상 지분율·주식 종류·상대방·목적을 표시한다. 실제 내역은 기존 표와 필터를 유지한다.
- 매일 오전 07:30(KST) 기존 `update-data.yml` 예약 및 수동 갱신 버튼에서 수집·집계한다. API 키는 기존 `DART_API_KEY` 환경변수/CI Secret만 사용한다.

```powershell
python scripts/fetch_gift_plans.py
python scripts/aggregate_gift_plans.py
python -m unittest discover -s scripts -p test_gift_plans.py -v
node scripts/test_gift_plans.cjs
```

실제 이행 확인에는 후속 소유상황보고서가 필요하다. 현재는 두 표의 원문을 통해 확인하며 이름·수량 유사성만으로 계획과 실제를 자동 매칭하지 않는다.

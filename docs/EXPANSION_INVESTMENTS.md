# 증설 투자 공시

`#/expansion`에서 코스피·코스닥 신규시설투자 공시를 조회한다. 기업·제품·시장·투자 분류·공시기간으로 필터링하고 투자목록과 변경이력을 따로 표시한다. 새 투자는 최신 계획 1행이며 원공시와 정정본을 다시 더하지 않는다. 금액 합계 차트는 제공하지 않는다. 모회사와 자회사가 같은 실물투자를 각각 공시할 수 있기 때문이다.

## 수집과 원문

- `scripts/fetch_expansion.py`: OpenDART 거래소 수시공시(`I001`) 목록에서 제목에 `신규시설투자`가 있는 공시를 찾고, 공개 DART 본문의 표를 읽는다. 공시 원문 ZIP은 공개 뷰어 정보를 얻지 못하는 경우의 대체 경로다.
- `scripts/expansion_document.py`: 정정표의 정정 전 숫자를 읽지 않도록 마지막 `1. 투자구분`부터 시작하는 본문을 파싱한다. 투자구분·대상·목적, 금액·자본 대비 비율, 기간, 투자주체와 공시된 생산규모를 보존한다. 금액의 원화 단위가 확인되지 않으면 추정 환산하지 않는다.
- 공식 DART `family` 본문 선택 목록의 접수번호로 관계를 확인한다. 같은 회사·같은 날짜·비슷한 제목만으로 투자건을 합치지 않는다. 조회기간 밖 원공시·정정본도 공식 연결 관계에 포함되면 함께 수집한다.
- 원문별 실패 상태와 이전 파싱 결과를 보존해 다음 실행에서 재시도한다. 최신 본문을 확인하지 못한 프로젝트는 `확인 필요`이며 종전 확인 금액을 구분해 표시한다. 조회 목록 자체가 실패하면 조회 완료일을 앞당기지 않는다.
- `data/expansion/source_state.json`에 공개 접수 정보·연결 관계·원문 파싱 결과를 보존한다. API 키나 인증 요청 URL은 기록하지 않는다. 다운로드한 불변 본문은 `.cache/expansion/`에 캐시한다.

## 분류와 표시

투자구분·대상·목적의 명시적 표현으로 분류한다. `생산 증설`, `신설·신사업`, `확인 필요`, `기타 시설투자` 네 분류이며, 기본 보기는 앞의 두 분류다. 교체·노후 개선·비생산시설이 생산 증설과 섞인 경우는 보수적으로 확인 필요로 남긴다. 분류 근거와 투자목적 원문은 상세에 표시한다. 전체 공시의 업황 설명에 있는 ‘증설’이라는 단어만으로 해당 회사 투자를 증설로 분류하지 않는다.

투자금액은 총 투자계획액이며 분기 실제 CAPEX·장비 발주액·확정된 미래 매출이 아니다. 완료 예정일 경과는 준공 확인이 아니다. 생산능력 증가 수치가 미공시된 경우 추정하지 않는다. 개별 신규시설투자 공시를 하지 않은 투자 및 다른 종류의 공시에만 나타나는 투자는 이 범위에서 포착하지 못한다.

## 실행

```powershell
python scripts/fetch_expansion.py --from 20251113 --to 20261113
python scripts/aggregate_expansion.py
```

시장 전체 조회에는 환경변수 `DART_API_KEY`가 필요하다. 처음에는 최근 365일을 조회하며 이후 성공한 조회 완료일에서 7일 겹쳐 증분 조회한다. `--refresh`는 기존 원문도 현재 파서로 다시 확인한다. 분류·파싱 규칙을 바꾸면 `PARSER_VERSION`도 올린다.

이미 내려받은 본문만 현재 규칙으로 다시 읽으려면 `python scripts/fetch_expansion.py --reparse-cache`를 실행한 뒤 집계한다. 수집 대기열과 중간 결과도 저장해 시간 제한으로 중단된 실행을 다음 수집에서 이어갈 수 있다.
저장된 접수번호의 공개 본문만 재수집할 때는 `--pending-only`를 사용한다. 이 모드는 시장 목록을 조회하거나 조회 완료일을 변경하지 않으며 공개 DART 뷰어로 읽을 수 있는 자료에는 API 키가 필요하지 않다.

`update-expansion.yml`이 매일 07:45 KST에 수집한다. 수집 중 일부 원문이 실패해도 성공한 자료와 실패 상태를 저장하고, 마지막에 실행 실패를 알린다. 성공한 수집 실행이 끝나면 Pages를 배포한다. 실패한 실행에서 저장한 중간 자료는 다음 성공한 배포에 반영된다. 소스 실패를 ‘공시 없음’으로 처리하지 않는다. 관련 워크플로만 자기 파일을 커밋한다.

검증은 `python -m unittest discover -s scripts -p test_expansion.py -v`와 `node scripts/test_expansion.cjs`를 사용한다. 실제 공시 fixture는 `scripts/fixtures/expansion/manifest.json`의 접수번호와 대응한다. DART 원문 링크는 `https://dart.fss.or.kr/dsaf001/main.do?rcpNo=<접수번호>`다.

# 에스앤에스텍 생산능력·생산실적

종목 101490, DART 고유번호 00411048. DART 정기보고서의 **II. 사업의 내용 → 생산 및 설비**에서 본사 및 공장의 블랭크마스크만 수집한다. Chemical·TSP·투자·컨설팅·부동산 등 기타 사업은 제외한다. 공개 검색과 HTML 뷰어를 이용하므로 API 키가 필요 없다.

## 확보 범위와 차트

2000년부터 2026-10-07까지 정기보고서를 검색한 결과, 2009 Q1~2026 Q2의 70개 보고서를 확보했다. 과거 연도 비교 열의 금액도 보존한다.

| 차트 | 확보 범위 | 해석 |
|---|---|---|
| 분기 생산실적 금액 | 2012 Q1~2026 Q2, 58분기 | 원문 천원을 억원으로 환산. 생산실적이며 매출이나 장수 아님 |
| 분기 가동가능시간·실제가동시간 | 2009 Q1~2026 Q2, 유효 68분기 | 생산능력 장수의 대체 공시값 아님. 설비·공정의 시간 합계 |
| 분기·누적 가동률 | 같은 기간 | 실제시간÷가능시간. 분기 가동률과 연초 누적 가동률을 구분 |
| 연간 생산실적 금액 | 2009~2025, 17개 연도 | 후속 보고서의 비교 열을 포함. 최신 비교값 우선 |
| 과거 분기 생산실적 수량·생산능력 | 실적 2009 Q1~2011 Q3, 능력 2009 Q1~Q4 | 공시된 수량만 사용. 반도체·디스플레이는 크기가 다름 |
| 연간 생산능력의 분기 공시 시점 | 2009 Q4~2011 Q3, 8개 보고서 | 해당 보고서가 공시한 연간 생산능력 94,104장/년. 분기 생산능력 아님 |

2011년 연간 보고서부터 생산실적은 장수에서 금액으로 바뀐다. 생산능력은 수량 대신 **시간당 생산성×1일 작업시간×작업일수, 최소 공정 기준**이라는 산정 방식만 공개한다. 따라서 최근 연간 장수·분기 장수는 추정하여 채우지 않는다. 생산금액÷가동률로 생산능력을 역산하지 않는다. 금액과 가동률의 측정 기준이 다르고 제품 구성·단가도 달라진다.

## 분기 변환과 원문 이상값

- Q1 = 3개월 누적, Q2 = 반기−Q1, Q3 = 9개월−반기, Q4 = 연간−9개월.
- 같은 해의 직전 누적값과 동일한 측정 단위가 있어야 계산한다. 연간값을 4로 나누지 않는다. 2011 Q4는 단위 전환으로 분기 금액과 장수 모두 계산할 수 없다.
- 2010~2011 Q3 생산능력은 분기보고서에서도 **연간** 기준이다. 누적값 차감 대상으로 사용하지 않는다. 2009년 생산능력은 해당 기간 누적 기준이므로 분기 차감할 수 있다.
- 2020 Q1 시간 원문은 53,856시간·41,969시간으로, 2019년 연간값과 같고 2020년 반기 누적값 33,024시간·25,577시간보다 크다. 원문은 그대로 저장하되 2020 Q1을 계산에서 제외했다. 그 값이 필요한 Q2 분기 시간·가동률도 결측이다. Q2 누적 가동률과 Q3 이후 분기 계산은 가능하다. 보간선으로 연결하지 않는다.
- 2015 Q1·Q2·Q3 생산실적 표의 당기 헤더에는 2014년이라고 적혀 있으나 보고서 기간과 제15기는 2015년이다. 이 특정 오기는 2015년으로 해석하고 원래 헤더와 근거를 보존한다. 새로운 형태의 기간 불일치는 자동 보정하지 않고 수집을 중단한다.
- 2011년·2021년 연간 금액은 후속 비교 열에서 바뀐다. 연간 차트는 가장 최근 정기보고서의 동일 연도·단위·사업 범위 값을 사용한다. 분기 차트는 해당 기간 정기보고서의 누적값으로 계산한다. 후속 연간 비교값과 당시 분기 합계 사이의 차이는 숨기지 않는다.
- 품목별 생산실적·시간은 반도체와 TFT-LCD를 합산한다. 평균가동률은 공시 %의 단순평균이 아니라 시간 합계 비율이다. 원문의 반올림 가동률과 작은 차이가 있을 수 있다.

## 기록과 자동 갱신

`data/_snstech/production_reports.json`: 접수번호, 공시명·기간, 생산능력 문장·기준, 생산실적 표의 당기·비교연도 값, 가동시간 원문 표, 예외 사유, 원문 뷰어 링크. 같은 기간 정정 보고서가 들어오면 가장 최근 접수번호를 선택하며 이전 기록은 보존한다.

`data/_snstech/production_quarterly.csv`: 70개 분기의 계산 결과, 원문과 직전 누적 보고서 접수번호, 계산 제외 사유. 차트 JSON의 `point_sources.reports`에도 계산에 사용한 보고서들을 넣는다.

```powershell
python scripts/fetch_snstech_production.py --backfill
python scripts/fetch_snstech_production.py
python scripts/fetch_snstech_production.py --offline
python -m unittest discover -s scripts -p test_snstech_production.py
```

매일 기존 데이터 갱신 워크플로에서 최근 약 2~3년의 제출을 확인한다. 새 접수번호·정정 보고서만 원문을 받아 계산한다. 초기 수집과 오래된 정정 확인은 `--backfill`로 수행한다. 검색은 4년씩 나누고 페이지를 처리한다. 수집·파싱·검증이 실패하면 기존 산출물을 덮어쓰지 않는다. `--offline`은 저장한 원문 추출 기록만으로 재생성한다. 연구용 HTML 캐시는 `--cache-dir tmp/pdfs`에서만 사용하며 커밋하지 않는다.
